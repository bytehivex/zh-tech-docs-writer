# AI 腔与套话清洗核对清单

本参考文件用于排查和清洗大语言模型（LLM）生成中文技术文档时的高频套话、空泛修饰与虚浮句式。

## 清洗原则

1. **直接陈述**：删除没有信息增量的背景引子与过渡句。
2. **事实替代修饰**：使用指标、代码、配置与命令替代「强大」「优雅」「一站式」等形容词。
3. **拆解复合句式**：避免「不仅……更……」与设问自答，改为并列或陈述句。
4. **拒绝动词虚化**：动词直接使用，不套用「进行修改」「做出优化」。

---

## 高频对照表

| 严禁的 AI 腔写法 | 改法与替代原则 | 样例 |
|---|---|---|
| **开场背景套话**<br>`随着……的不断发展`<br>`在当今数字化时代`<br>`作为……的重要组成部分` | 彻底删除，首句直接陈述模块用途或解决的问题。 | `❌ 随着微服务架构的不断发展，配置管理已经成为一个不容忽视的问题。`<br>`✅ ConfigHub 用来集中管理多个微服务的配置。` |
| **引子套话**<br>`值得注意的是`<br>`需要指出的是`<br>`让我们来看看`<br>`接下来我们将介绍` | 删除引子，直接陈述事实；确需提醒的事项使用引用块或提示标签。 | `❌ 值得注意的是，该参数仅在调试模式下生效。`<br>`✅ 该参数仅在调试模式生效。` |
| **结尾升华与客套**<br>`总的来说`<br>`综上所述`<br>`总而言之`<br>`希望对你有帮助`<br>`如有疑问欢迎交流` | 彻底删除总结段与客套语。若需收尾，仅列出具体的下一步操作。 | `❌ 综上所述，遵循以上规范能让项目更健壮，希望对你有帮助！`<br>`✅ [直接结束，或提供下一步操作链接]` |
| **设问自答**<br>`为什么需要这样做？因为……`<br>`核心原因是什么？很简单：` | 删除设问，直接陈述因果逻辑。 | `❌ 为什么需要开启双因子认证？答案很简单：为了防止撞库攻击。`<br>`✅ 开启双因子认证可以防止凭证泄露导致的撞库攻击。` |
| **机械递进与转折**<br>`不仅……而且/更……`<br>`与其说 A，不如说 B`<br>`不是 A，而是 B` | 拆成两个独立的客观陈述句，或直接陈述事实 B。 | `❌ 该网关不仅支持 HTTP/3，更实现了零拷贝转发。`<br>`✅ 该网关支持 HTTP/3，并采用零拷贝转发机制。` |
| **宣传腔形容词**<br>`强大`<br>`优雅`<br>`极致`<br>`无缝`<br>`全面`<br>`轻松应对`<br>`一站式解决方案` | 替换为具体指标与规格；若无数据支撑直接删除。 | `❌ 该组件提供了强大的并发处理能力，助你轻松应对高并发场景！`<br>`✅ 该组件单节点实测支持 50,000 QPS，P99 延迟低于 5 ms。` |
| **动词虚化与翻译腔**<br>`对……进行修改`<br>`做出优化`<br>`通过……的方式实现`<br>一句连续多个「的」 | 直接使用动词；拆开长定语。 | `❌ 对服务器配置文件进行更新。`<br>`✅ 更新服务器配置文件。` |
| **过度含糊与连环叠甲**<br>`在某种程度上`<br>`在一定情况下可能会`<br>`大概也许` | 确定的事实直接陈述；不确定时说明具体依赖条件和验证方式。 | `❌ 开启此选项可能会在某种程度上提升系统稳定性。`<br>`✅ 在网络丢包率高于 2% 时，开启此选项可减少超时重试。` |
| **空泛互联网黑话**<br>`赋能`<br>`抓手`<br>`闭环`<br>`沉淀`<br>`对齐`<br>`拉通`<br>`颗粒度` | 替换为具体工程动作。 | `❌ 赋能开发团队，拉通各端数据，形成能力闭环。`<br>`✅ 为开发团队提供统一接口，打通跨端数据上报。` |
